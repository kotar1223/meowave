# Аккаунты площадок

Запрос (раунд 5): «сделай так, чтобы можно было подключать свои аккаунты с площадок: оттуда импортировать треки и для шторки брать подборки».

Настройки → **Аккаунты**: карточка на каждую площадку — YouTube Music, SoundCloud, Deezer, Яндекс Музыка, Spotify. На карточке статус («Вы вошли как …»), что даёт вход и кнопки «Войти», «Вставить ключ», «Импорт», «Выйти». Внизу — «Импорт по ссылке» (прежнее окно импорта, без входа).

## Вход
- **YouTube Music, SoundCloud, Deezer.** «Войти» открывает отдельное окно со страницей входа самого сервиса (Google, soundcloud.com, deezer.com). Пароль вводится на странице сервиса, Meowave его не видит. У каждого аккаунта своя папка данных окна (`accounts/<id>` в данных приложения). Rust раз в 1,5 с читает куки окна; как только появилась сессия, проверяет профиль, сохраняет ключ и закрывает окно (ждёт до 10 минут). Карточка обновляется по событию `acc-changed`.
  - YouTube Music — куки Google (`SID`, `HSID`, `SSID`, `APISID`, `SAPISID`, `__Secure-1PSID`, `__Secure-3PSID` и др.); запросы подписываются `SAPISIDHASH`, как у веб-клиента music.youtube.com.
  - SoundCloud — кука `oauth_token`.
  - Deezer — кука `arl`.
- **«Вставить ключ»** — запасной путь, если окно входа не пускает (Google иногда отказывает встроенным окнам). В диалоге написано, где взять в своём браузере заголовок `Cookie`, `oauth_token` или `arl` (F12). Поле скрытое, до 16 384 символов.
- **Яндекс Музыка** — прежний вход через аккаунт Яндекса или по токену.
- **Spotify** — прежний вход со своим Client ID; Client ID теперь спрашивается в диалоге.
- Ключи хранятся только в системном keychain (`tokens.rs`). Длинные (куки Google — несколько килобайт) пишутся частями по 1000 символов: Credential Manager Windows держит не больше 2560 байт на запись.
- «Выйти» удаляет ключ и папку окна входа. Перенесённые треки и плейлисты остаются.

## Импорт
- «Импорт» раскрывает список: «Любимые треки» (попадут в избранное) и плейлисты аккаунта. Можно перенести один список или «Перенести всё».
- Плейлист помечается `src` = `<сервис>:<id>`: повторный импорт дописывает тот же плейлист, а не создаёт копию. В избранное трек второй раз не попадает.
- Треки приходят готовыми, без поиска по одному: до 5000 за раз. Играют с родной площадки.

## Шторка
- Подключённый аккаунт добавляет первой полку **«Ваша библиотека»** на вкладке сервиса: любимые треки и ваши плейлисты.
- YouTube Music со входом показывает сначала личную главную (`FEmusic_home` от вашего имени), SoundCloud — подборки «для вас» (`/mixed-selections`).
- После входа или выхода кэш шторки сбрасывается (`hsForget`).

## Код
- Rust: `src-tauri/src/accounts.rs` — команды `acc_status`, `acc_login`, `acc_paste`, `acc_logout`, `acc_lists`, `acc_tracks`; `shelves()` и `open()` для шторки и страниц подборок. Подписанные запросы YouTube Music — `ytm.rs` (`sapisid_hash`, `post_signed`, `account`, `signed_shelves`, `signed_playlists`, `signed_tracks`). `feeds.rs` — полки и открытие подборок, `tokens.rs` — ключи по частям.
- Фронтенд: `app.js` — `renderAccounts`, `accCard`, `accLists`, `accImport`, `accImportAll`, `accLogin`, `accPaste`, `accLogout`, `importRows`; стили `.acc-*` в конце `app.css`; `discover.js` — `hsForget`.

## Ограничения
- Проверено кодом, юнит-тестами и скриншотами на подставных данных; настоящих аккаунтов в песочнице нет.
- Google может не пустить во встроенное окно — тогда «Вставить ключ».
- API SoundCloud (api-v2) и Deezer (gw-light) неофициальные.
- Аккаунт YouTube Music не помогает воспроизведению (см. [[Features/Streaming]]): им читаются только библиотека и подборки.
